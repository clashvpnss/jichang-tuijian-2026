### 🧭 选购决策与费用

> 选机场的顺序常被搞反：先比速度，最后才发现订阅导不进客户端。这一节按「买之前能确认的」到「买之后才知道的」排列。

#### 机场和 VPN 有什么区别？

商业 VPN 通常是「一个 App 打包一切」：服务器、客户端、协议都由一家公司提供。机场是分离的——服务商只给节点和一条订阅链接，客户端由你自己选（Clash、Shadowrocket、v2rayN 等）。机场的可配置性更强，能按域名或应用做规则分流；代价是上手门槛更高。协议上也不同：VPN 多用 OpenVPN、WireGuard，机场多用 Shadowsocks、Trojan、VLESS 这类为对抗流量识别设计的方案。

#### 机场和梯子是一回事吗？为什么叫机场？

日常语境里基本可以互换。「梯子」是泛称，「机场」特指提供节点订阅的平台。这个叫法源于早期常用客户端的图标是纸飞机，一个节点也被称作一次「航班」。「科学上网工具」「魔法上网」是同类的委婉说法。

#### 新手第一次买机场，最该看什么？

按顺序：① 订阅格式能否被你的客户端读懂（读不懂等于不能用，与速度无关）；② 是否支持月付（先花最少的钱试，别为年付折扣锁一年）；③ 流量、限速、设备数是否写在套餐页上；④ 最后才看速度。前三项购买前都能确认，速度只能自己测。

#### 机场节点是越多越好吗？

不是。一百个拥挤的公网节点，体验可能不如五个稳定的专线节点。数量的价值在容灾和地区覆盖——某节点被封时有替代，以及你需要的地区都有。判断应看地区覆盖是否满足需求，以及晚高峰时有多少节点仍可用。

#### 机场节点倍率是什么意思？

倍率是流量的计费系数。倍率 1 表示用 1GB 扣 1GB；倍率 3 表示用 1GB 扣 3GB。高倍率通常出现在成本更高的节点上（如专线、原生 IP 落地）。看套餐时务必确认哪些节点是高倍率，否则流量会比预期消耗得快得多。

#### 机场流量每月会重置吗？用完了怎么办？

周期套餐通常按订单日每月重置，具体以商家规则为准（有的按自然月）。用完后一般可以购买流量包续上，或等下个重置日。如果你的用量不规律，一次性的不限时流量包可能比包月更合适——流量不作废。

#### 机场晚高峰卡顿正常吗？为什么白天快晚上慢？

一定程度的波动是正常的。21:00–23:00 是国际出口最拥堵的时段，公网线路要与大量用户争抢带宽，因此白天与晚上的差距可能很明显。IPLC/IEPL 专线绕开了公网出口，晚高峰波动通常更小，但成本高得多。如果晚高峰完全不可用，才是需要考虑更换的信号。

#### 机场节点全红、显示超时怎么办？

先区分是「延迟测试超时」还是「实际连不上」。前者常见于机场屏蔽了客户端默认的测试地址，换一个测试 URL 即可。后者按顺序排查：系统代理是否开启、订阅是否过期、本地时间是否准确（偏差超过 90 秒会导致部分协议握手失败）、以及是否被本地防火墙或安全软件拦截。

#### 月付、季付、年付该选哪个？

优先月付。机场行业的经营周期普遍不长，年付折扣通常覆盖不了资金锁定一年的风险敞口。折扣本质上是你用风险换来的价格。建议先月付试满一个月，确认晚高峰表现稳定后，再考虑是否延长周期。

#### 按量计费和包月哪个划算？

看用量是否规律。包月的单位流量价格明显更低，但流量按月清零。按量计费或不限时流量包单价高，换来的是不必按月续费、流量不作废。每天固定使用选包月；出差备用、偶尔应急选按量。

#### 免费试用的机场安全吗？

官方提供的限时或限量试用与「免费公共节点」是两回事。前者是商家的获客手段，用的是正式服务的节点，风险与付费套餐相当。后者来路不明，运营成本可能通过广告、限速或记录流量数据收回。试用期间建议不要登录重要账号或涉及支付。

#### 低价机场有什么风险？

主要有三类：一是超售，用户数远超带宽承载，表现为晚高峰严重卡顿；二是线路标称与实际不符（标专线实为公网中转）；三是经营不稳定，低价可能是获客后难以持续的信号。低价本身不是问题，关键是搞清楚便宜在哪里——是限速、限流量、高倍率，还是线路降级。

#### 机场节点地区怎么选？香港、日本、新加坡、美国有什么差别？

按用途选：香港与日本物理距离近，延迟最低，适合游戏、语音通话和日常浏览；新加坡延迟略高但线路通常较稳定，适合长时间下载；美国延迟最高（普遍 150ms 以上），但 AI 服务与部分流媒体的内容库最全。流媒体则要看内容归属地——想看某国的内容就得连该国节点。

#### 机场可以长期使用吗？会不会突然用不了？

服务停止运营是这个行业的结构性风险，无法完全避免，只能分散。实际做法是：优先月付、保留第二家备用、导出当前可用的节点配置作离线备份。这样单一来源失效时，损失控制在一个月的费用与一次迁移的时间内。

#### 机场订阅突然不能用了，是跑路了吗？

不一定。更常见的原因是订阅域名被封锁、节点批量更换、或客户端缓存了旧配置。先把订阅链接直接粘到浏览器打开：能下载到配置说明服务仍在，问题在客户端；打不开则需要进一步确认是域名不可达还是站点本身停止。

#### 机场共享账号安全吗？

不建议。多数机场限制同时在线设备数，共享容易触发风控导致封号；订阅链接一旦外泄，他人可无限使用你的流量；更重要的是，共享方能看到你的使用情况。费用分摊省下的钱，通常抵不过这些风险。

#### 机场能解锁 Netflix、Disney+ 吗？

取决于落地 IP 的属性和平台当时的风控策略，不取决于机场的宣传。住宅 IP 通常比机房 IP 更容易通过检测，但没有任何 IP 类型可以保证长期有效——平台策略持续调整，今天能用不代表下个月还能用。任何「永久全解锁」的说法都不可信，建议购买前用开源脚本自行检测。

#### 机场能用 ChatGPT、Claude 这类 AI 工具吗？

多数可以，但稳定性差异很大。AI 平台对机房 IP 的风控通常比流媒体更严格，可能表现为频繁的人机验证或直接拒绝访问。选择时优先确认落地是否为原生住宅 IP，并注意频繁切换节点本身也可能触发验证。

#### 自建服务器和买机场哪个更划算？

看时间成本和用量。自建的月支出可以很低，节点完全独享、不与他人争抢带宽；代价是搭建、维护、协议更新和 IP 被封后的迁移全归你。机场把这些成本摊进了订阅费。用量小又不想折腾选机场；有技术能力且长期高强度使用，自建的单位成本更低。

#### 为什么有的机场不给订阅链接，要联系客服？

部分机场以此控制订阅外泄，属于合理的运营策略。但这意味着客服本身成了产品的一部分——首次配置、订阅重置、换设备都要走这条路。如果遇到这种情况，建议付款前先发一条咨询测试响应速度，这比任何测速数据都更能预测日后的体验。

### 🛰️ 线路类型与 IP 属性

> 「IEPL 专线」「BGP 中转」「原生 IP」是价格差异的主要来源，也是最容易被含糊标注的地方。这一节说明它们各指什么，以及怎么自己核实。

#### 专线机场是什么意思？

专线指服务商向运营商租用的跨境物理线路（IPLC / IEPL），流量走独享通道，不与公网用户争抢国际出口。优点是晚高峰的丢包与抖动通常明显更小；代价是按带宽计费、成本高，所以专线机场普遍更贵。要验证商家的专线标称是否属实，可以用 BestTrace 或 mtr 跑一次路由追踪。

#### 中转机场是什么意思？

中转指流量先发到国内的入口服务器，再由它转发到海外落地机。入口通常做了多线优化（BGP），能为不同运营商的用户选择较优路径。成本远低于专线，日常使用多数够用，但骨干网极端拥堵时仍会受公网状况牵连。

#### 直连机场是什么意思？

直连指客户端直接连接海外服务器，中间不经过国内中转。链路最短、结构最简单，成本也最低。缺点是完全依赖公网国际出口的状况，晚高峰波动通常最明显，且更容易受到干扰。

#### 专线机场和中转机场哪个好？

没有绝对优劣，取决于预算和用途。对延迟和稳定性要求高（游戏、语音、直播、商务）选专线；日常浏览、看视频，优质中转的性价比明显更高。实际判断建议先买最低档月付，用路由追踪确认线路结构，再在晚高峰实测三天。

#### 直连机场和中转机场有什么区别？

区别在国内这一段。直连是你的设备直接连海外服务器；中转是先到国内入口服务器，由它优化路由后再出境。中转通常能改善国内段的路由质量，尤其对移动、联通用户；直连则少一跳、结构更简单。哪个更快取决于你的宽带线路，需自己实测。

#### 专线机场为什么更贵？

因为成本结构不同。IPLC / IEPL 是运营商按带宽包月计费的产品，服务商买多少带宽就付多少钱，且这个成本不随用户数摊薄——用户越多，每人分到的带宽越少。公网中转则可以超售。所以看到标称专线却价格极低的套餐，值得追问是否全节点走专线、是否限速限流量。

#### 机场原生 IP 是什么意思？

原生 IP 指由节点所在地当地运营商分配的 IP，归属地与服务器物理位置一致。相对的是「广播 IP」——从其它地区路由过来的 IP，归属地与服务器位置不符。流媒体和 AI 平台通常更信任原生 IP，但这不是保证，平台的判断依据还包括 IP 类型、历史行为等多个维度。

#### 机场住宅 IP 是什么意思？

住宅 IP 指运营商分配给普通家庭宽带的 IP，与数据中心（机房）IP 相对。因为它看起来像真实居民在上网，流媒体和 AI 平台的风控通常较宽松。成本明显高于机房 IP，所以提供住宅 IP 的套餐通常价格更高或流量倍率更大。

#### 机场动态 IP 和静态 IP 有什么区别？

静态 IP 长期固定不变，动态 IP 会定期或每次连接时变化。静态 IP 对需要 IP 白名单的场景（企业系统、部分 API）是必需的；动态 IP 则在单个 IP 被平台标记时能自动换掉，但频繁变化也可能触发风控要求重新验证。多数机场使用动态或共享 IP，需要静态 IP 通常要单独购买。

#### 机场为什么有些节点不能看流媒体？

流媒体平台按 IP 判断你所在的地区并识别代理。能否解锁取决于三点：IP 归属地是否为该内容的可用区、IP 是住宅还是机房类型、以及该 IP 是否已被平台标记。同一家机场内不同节点的 IP 来源不同，所以解锁情况差异很大，通常只有部分节点可用。

#### 机场为什么有些节点不能用 AI 工具？

AI 平台对机房 IP 的风控通常比流媒体更严格，且部分服务限制特定国家或地区。表现可能是频繁的人机验证、要求手机验证，或直接拒绝访问。另外频繁切换节点本身也会触发风控——选定一个可用节点后尽量固定使用。

#### 机场能解锁 Disney+ 吗？

取决于具体节点，不取决于机场的宣传。Disney+ 各区内容库不同，你需要连接对应地区且未被标记的节点。任何「全解锁」的说法都只代表某个时间点——平台风控策略持续调整。建议购买前用开源脚本自行检测，或先买最低档月付验证。

#### 机场能看 YouTube 吗？

绝大多数机场都能访问 YouTube，这是门槛最低的需求。真正的差别在于能否流畅播放 4K 甚至 8K，那取决于晚高峰的可用带宽而非能否连通。另外 YouTube Premium 的可用性与账号注册地相关，与节点地区未必一致。

#### 机场能用 TikTok 吗？

可以，但比看视频要求更高。TikTok 对 IP 与设备环境的风控较严，机房 IP 容易被限流或触发验证。如果只是浏览，多数节点够用；如果要做内容运营或多账号，通常需要住宅原生 IP，且要注意同一 IP 下的账号数量。

#### 机场能用 Claude 吗？能用 Gemini 吗？

多数可以，但稳定性因节点而异。这类 AI 服务对 IP 类型敏感，机房 IP 更容易遇到验证或拒绝。另外部分服务对可用地区有限制，需要选对应地区的节点。建议先用小额套餐实测你实际要用的那个服务，不要依赖宣传清单。

### 💳 流量、倍率与付费周期

> 同样标价 20 元的套餐，实际成本可能差三倍——差在倍率和重置规则上。这一节是关于「你到底花了多少钱」。

#### 不限时机场是什么意思？

指一次性购买固定流量、用完为止、不设有效期的套餐，与按月订阅相对。单位流量价格通常明显高于包月，换来的是不必按月续费、流量不作废。适合用量不规律、出差备用或低频使用的人。

#### 不限时机场和月付机场哪个好？

看用量是否规律。每天固定使用，包月的单位流量价格低得多；一个月只用几次，包月的流量会大量作废，不限时包反而更划算。也可以两者结合：主力用包月，另买一个小额不限时包作为备用。

#### 月付机场适合哪些用户？

适合所有人，尤其是新用户。月付是这个行业最有效的风险控制手段——机场经营周期普遍不长，月付把单次损失控制在一个月的费用内。建议无论最终选哪家，都先月付试满一个月，确认晚高峰表现稳定后再考虑更长周期。

#### 季付机场划算吗？年付机场值得买吗？

从单价看划算，从风险看未必。折扣本质上是你用「资金锁定更长时间」换来的。判断标准是：这家你已经用满至少一个月、晚高峰表现稳定、且官方沟通渠道正常更新。满足这些再考虑季付，年付则建议只给已经用了很久的服务。

#### 机场买月付还是年付？

优先月付。年付折扣通常在 3 到 5 折之间，看起来很划算，但如果服务在第四个月停止运营，你实际支付的单月成本反而更高。稳妥的做法是：月付试用 → 满意后季付 → 长期稳定后再考虑年付。

#### 机场流量倍率怎么计算？

倍率是流量的计费系数。倍率 1 表示消耗 1GB 扣除 1GB；倍率 2 表示消耗 1GB 扣除 2GB。高倍率通常出现在成本更高的节点上（专线、住宅 IP 落地）。计算实际可用量时要按你常用节点的倍率折算——150GB 套餐全程走倍率 3 的节点，实际只有 50GB。

#### 机场流量用完了怎么办？

通常有三个选择：购买额外流量包续上、升级到更高档套餐、或等待下个流量重置日。重置规则各家不同，多数按订单日每月重置，也有按自然月的，购买前值得确认。如果经常在月中用完，说明套餐档位选低了。

#### 小流量用户适合买什么机场？

每月用量在 50GB 以内的话，优先看两类：低价档月付套餐，或一次性不限时流量包。后者对用量不规律的人更友好——不会因为某个月没怎么用就白付钱。不建议为了「更划算」买大流量套餐，用不完的流量多数会作废。

#### 大流量用户适合买什么机场？

每月数百 GB 以上的用量，重点看三项：套餐的流量单价、是否限速、以及常用节点的倍率。倍率对大流量用户的影响被放大——倍率 2 意味着实际成本翻倍。另外要确认是否限制并发连接数，重度下载与多设备同时使用容易触及这个限制。

**月付价格不等于实际成本。先确认高倍率节点有哪些，再算每月真实可用流量。**

### 🎬 流媒体与特定服务风控

> 打不开 Netflix 或 ChatGPT，多数时候不是机场慢，而是落地 IP 被识别。这一节帮你分清是节点问题还是 IP 属性问题。

#### 为什么挂了机场的美国节点，登录 ChatGPT 依然提示 Access Denied（错误码 1020）？

OpenAI 对机房 IP 的风控极严。这个报错说明该节点的 IP 被 OpenAI 列入了黑名单。请尝试清除浏览器 Cookie，开启无痕模式，并切换到机场标注有“解锁 OpenAI/ChatGPT”的专用原生节点。

#### 为什么看 Netflix（网飞）时提示“您似乎在使用解锁工具或代理”？

Netflix 封锁了商业机房的 IP 段。非解锁节点只能看 Netflix 自制剧，无法看到锁区剧集。解决办法是让机场主更换节点 IP，或切换到专门的流媒体解锁节点。

#### 为什么挂了日本节点，刷 TikTok（抖音海外版）却提示黑屏、无网络连接？

TikTok 不仅检测 IP，还会强制检测你手机里 SIM 卡的国家代码（MCC）。中国大陆的 SIM 卡（460）会被直接拒绝。你需要拔出 SIM 卡，或者在手机客户端使用特定脚本（如 Quantumult X/Loon 的重写规则）来伪装运营商信息。

#### 节点选了台湾，为什么打开 Google 弹出的广告全都是越南语？

这叫 IP 广播污染。这个 IP 以前可能被用在越南机房，最近被买下并广播到了台湾，但 Google 的地理位置数据库还没更新，需要等待 Google 自动修正。

#### 开着机场去玩 Steam/Epic 外服游戏，为什么延迟极高还经常掉线？

普通机场节点针对的是网页和视频的 TCP 流量，而游戏联机大量使用 UDP 流量。很多机场为了省带宽会关闭 UDP 转发，或者其路由没有经过游戏优化。玩游戏建议使用专业的“游戏加速器”，而不是普通网页机场。

#### 登录某海外加密货币交易所时，账号突然被冻结提示“合规风险”。

很多交易所（如币安、Coinbase）严禁美国或某些敏感地区 IP 访问。如果你把节点设为了全局美国，或者节点在中途漂移到了受限制地区，就会触发交易所的风控自动锁仓。

#### 为什么使用机场后，国内的网易云音乐、QQ音乐里很多歌都变成灰色了？

你的分流规则失效了，导致音乐 App 认为你是一个海外用户，由于版权保护（限大陆地区播放），歌曲自动变灰。需要确保分流规则中 NetEase 或 Tencent 走 Direct（直连）。

#### 为什么用香港节点访问某些网站，会跳出“当前国家/地区法律不予显示”？

部分网站（如部分特殊论坛或成人网站）根据当地合规要求，对中国香港本地的 IP 进行了主动屏蔽，更换为日本或新加坡节点即可访问。

**解锁状态随时会变，任何「保证解锁」的承诺都无法长期兑现。用开源脚本自测当下状态，比看宣传可靠。**

### 🛡️ 运营风险与故障应对

> 机场跑路、跳票、突然限速是这个行业的常态。这一节是关于怎么把损失控制在可接受范围内。

#### 机场跑路是什么意思？

指服务商停止运营、卷走预付款项。这个行业进入门槛低、经营周期普遍不长，服务停止是结构性风险而非个别现象。降低损失的实际做法是：优先月付、保留第二家备用、导出当前可用的节点配置作离线备份。

#### 怎么判断机场会不会跑路？

没有可靠的预测方法，只能观察一些相关信号：突然出现远低于常规水平的长期套餐促销、公告与状态页长时间停更、客服响应变慢、支付方式频繁变更。这些在正常经营中也可能出现，应当作提高警惕的提示而非结论。更实际的做法是自己核实运营状态：查域名注册信息、做站点探活、看公开渠道的更新节奏。

#### 机场官网打不开怎么办？

先分清是域名被封锁还是站点停止。分别用国内网络和代理网络访问：只有国内打不开，多半是域名被墙，找官方的备用域名即可；两边都打不开，才需要考虑站点本身的问题。多数机场会在 Telegram 频道或邮件里公告备用域名，购买后建议先保存这些渠道。

#### 机场换域名怎么办？

按官方公告的新域名重新登录即可，订阅链接通常也会随之变更，需要在客户端里更新。这是这个行业的常态——域名被封后更换是正常运营行为，不等于服务出了问题。建议提前关注官方的公告渠道，避免在换域名时以为服务停了。

#### 机场备用官网有什么用？

主域名被封锁时的入口。多数机场会准备多个域名轮换使用，并通过 Telegram 频道、邮件或客户端内公告发布。购买后建议第一时间保存这些渠道——等到主站打不开再找，往往找不到可信的来源，反而容易进到钓鱼站点。

#### 机场公告在哪里看？

常见渠道有三个：用户中心的站内公告、官方 Telegram 频道、以及注册邮箱收到的邮件。节点变更、域名更换、维护通知通常都从这些渠道发出。购买后建议至少订阅其中两个，避免单一渠道失效时错过重要通知。

#### 机场客服联系不上怎么办？

先确认渠道是否正确——部分机场只在用户中心内提供在线客服，站外渠道可能是仿冒的。如果官方渠道长时间无响应，配合官网可访问性、公告更新情况一起判断。单一渠道无响应通常是工作时间问题，多个渠道同时且持续无响应才值得担心。

#### 机场被封了怎么办？

先判断是账号被封还是节点被封。节点被封表现为部分节点不可用，更新订阅通常就能拿到替换节点，属于常态。账号被封则需要联系客服，常见原因包括超出设备数限制、共享账号、或触发了服务条款。购买前了解清楚设备数限制能避免多数此类问题。

**降低风险最有效的做法不是挑「不会跑路的」——没人能预判——而是别一次性买太长的周期。**

### 🔍 怎么判断评测与榜单

> 几乎所有机场榜单都有推广佣金，包括本站。这一节讲怎么从一份评测里分辨哪些是可核实的信息、哪些是包装。

#### 便宜机场靠谱吗？

价格本身不决定可靠性，关键是搞清楚便宜在哪里。常见的降本方式有：限速、限流量、高倍率、公网中转替代专线、机房 IP 替代住宅 IP。这些都是正当的取舍，只要明示就没问题。需要警惕的是价格明显低于成本线又宣称全专线全解锁的——那通常意味着某项标称不实，或经营难以持续。

#### 高性价比机场怎么判断？

把价格换算成可比单位：每 GB 多少钱，并按你常用节点的倍率折算。然后看这个价格买到的是什么线路、什么 IP 类型、有没有限速。同价位下线路等级更高的更划算，但前提是标称属实——用路由追踪验证过再下结论。

#### 机场优惠码在哪里找？怎么用？

通常来自三处：官方的活动公告、导航或评测站点的合作码、以及节日促销。使用方式是在结算页的优惠码栏填入。需要注意有些折扣是经推广链接自动生效的，不需要手动填码——两者通常不能叠加，实际以结算页显示的金额为准。

#### 机场优惠活动靠谱吗？一元试用值得买吗？

官方发布的活动本身没有问题，低价首月是常见的获客手段，也符合「用最小成本试错」的原则。需要确认三件事：优惠仅限首个周期还是长期有效、到期后按什么价格续费、以及是否自动扣款。问清楚再买即可。

#### 机场试用应该测试什么？

按优先级：① 订阅能否被你的客户端读取；② 你实际要用的服务能否访问（不要泛泛测「能不能翻墙」）；③ 晚高峰 21:00 到 23:00 的表现，至少覆盖两三个晚上；④ 客服响应速度。峰值速度反而最不重要——决定续不续费的是稳定性。

#### 机场购买前要注意什么？

四件事：订阅格式与你的客户端是否匹配、是否支持月付、流量与限速与设备数是否写在套餐页上、以及常用节点的倍率是多少。这四项在购买前都能通过看套餐页或问客服确认。速度无法事先确认，只能自己测。

#### 机场导航是什么？梯子导航是什么？

指汇总多家机场信息的站点，通常提供价格对比、线路说明和优惠码。需要知道的是：这类站点绝大多数通过推广链接获得佣金，包括本站在内。这不必然导致内容不可信，但意味着它们不是无利益立场的第三方，看结论时应留意依据是否可核实。

#### 机场排行榜靠谱吗？机场天梯榜靠谱吗？

要看排序依据是否公开且可验证。如果只给出名次而不说明凭什么排，那个顺序通常反映的是佣金高低而非服务质量。可信的榜单会说明每项数据的来源、哪些是厂商自述、哪些经过核实。看到「实测」二字时，可以留意有没有给出测试时间、工具和环境——没有这些，结果无法复现，也就无法验证。

#### 机场评测文章可信吗？

应当默认带着怀疑读。这个领域的评测绝大多数带推广链接，包括本站。判断方法有几个：是否区分了「厂商说法」与「作者结论」、是否承认有无法核实的部分、测速数据是否给出了可复现的条件（时间、工具、本地带宽）、以及是否只说优点。全是好话的评测，参考价值有限。

#### 机场推荐知乎可信吗？GitHub 可信吗？Reddit 可信吗？

平台本身不决定可信度，取决于内容形态。知乎与 Reddit 上的个人使用反馈有参考价值，但要留意软文和刷量；GitHub 仓库看起来技术感强，但批量生成的推广仓库同样大量存在——可以看仓库的提交历史、star 来源和内容是否雷同。任何平台上，能给出可复现依据的内容才值得采信。

#### 机场评测应该看速度还是稳定性？

稳定性。单次跑分再高，如果晚高峰频繁卡顿或掉线，日常体验依然很差。速度只要达到你的使用需求就够了——看 4K 视频约需 25Mbps 稳定带宽，远低于多数机场的标称峰值。判断稳定性需要连续观察数日，这也是建议先月付试用的原因。

#### 机场评测应该看价格还是线路？

先看线路是否满足需求，再在满足需求的范围内比价格。线路类型决定了能力上限——需要低延迟就得看专线，日常浏览优质中转即可。确定了线路档次之后，把价格换算成每 GB 单价并按倍率折算，才是有意义的比较。

#### 机场推荐里常见的坑有哪些？

常见的有几类：标称专线实为公网中转、宣传全解锁但仅部分节点可用、低价档限速或高倍率但不明示、设备数限制写在不显眼处、以及年付折扣诱导长期锁定。这些多数可以在购买前通过看套餐页和问客服确认，剩下的靠最低档月付实测。

#### 机场新手最容易踩哪些坑？

三个最常见：① 导入订阅后忘了打开客户端的系统代理开关，以为服务有问题；② 订阅格式与客户端不匹配导致节点不显示，误以为是速度问题；③ 为年付折扣一次锁定一年，遇到服务停运时损失最大。前两个是配置问题，第三个是决策问题。

### ⚠️ 客户端报错与玄学断网

> 节点全红、订阅导入失败这类问题，绝大多数不是机场坏了。这一节按「最可能」到「最少见」排查。

#### 为什么客户端显示节点全绿有延迟，但就是打不开任何网页？

大概率是本地系统代理没开，或者系统时间不同步。请检查电脑/手机的时间是否精确到秒，TLS 加密协议对时间差非常敏感，相差超过 1 分钟就会握手失败。

#### 为什么开启 Clash 代理后，微信能发消息，但浏览器打不开任何国内网页？

微信有内置缓存且部分流量走特定端口。浏览器打不开是因为 Clash 劫持了系统 DNS 但解析失败，可在软件设置中尝试关闭并重新开启“系统代理（System Proxy）”或切换为 TUN 模式。

#### 客户端日志里频繁提示 connection refused 是什么原因？

目标服务器拒绝了连接。可能是该节点刚好宕机了，或者是你的订阅长期未更新，该节点的端口在机场后台已经发生变更。

#### 什么是 TUN 模式？什么时候需要开？

TUN 模式会在系统层虚拟出一张网卡，强制接管整台电脑的所有流量。当你发现某些游戏、UWP 应用或终端命令行不走代理时，开启 TUN 模式可以解决 99% 的流量漏过问题。

#### 导入订阅时提示 invalid config 或配置文件解析错误怎么办？

说明下载的订阅文件格式损坏。通常是因为你的套餐过期/流量用尽，机场服务器返回了提示无流量的网页源码（HTML），客户端无法将其识别为 YAML/JSON 配置。

#### 为什么一开杀毒软件（如 360、火绒），机场节点就全部变成 Timeout？

杀毒软件的“网络防护”或“恶意流量拦截”功能误杀了代理软件的虚拟网卡驱动或本地回环端口（如 7890）。需要将代理软件的整个文件夹加入杀毒软件的白名单。

#### Mac 升级系统后，代理软件的系统代理开关勾选后瞬间自动弹开，无法开启。

系统权限冲突。需要在 Mac 的“系统设置 -> 网络 -> VPN 与过滤器”中，删掉旧的代理配置残余，并给当前代理软件重新授予“添加代理配置”的权限。

#### 为什么局域网内的 NAS 开了代理后，在外面用公网 IP 无法访问它了？

因为代理软件接管了外部入站流量的回程路由，导致回程流量走到了机场节点。需要在分流规则中加入你本地的 DDNS 域名或内网 IP 段，设置为 Direct（直连）。

#### 客户端提示 context canceled 是什么意思？

代表连接被主动取消。通常是你在网页还没加载完时切换了节点，或者浏览器发起了并发请求，其中较慢的连接被软件内核自动中止了，属于正常现象。

#### Windows 提示 wintun.sys 缺失或安装失败，导致无法启动软件。

TUN 模式所需的虚拟网卡驱动被系统阻止。请右键以管理员身份运行客户端，或者去 Wintun 官网手动下载该驱动文件放入软件对应的内核目录中。

**换机场之前先按顺序排查：订阅链接 → 客户端版本 → 系统时间 → 本地网络。多数「机场坏了」其实不是。**

### 📖 机场基础概念与黑话入门

> 如果上面的内容里有看不懂的词，从这一节开始读。

#### 机场是什么？

机场是提供网络代理（科学上网）节点订阅服务的平台。你购买套餐后获得一条订阅链接，导入 Clash、Shadowrocket 等客户端就能使用它提供的海外节点。因为早期常用客户端的图标是纸飞机，这类服务就被戏称为「机场」。

#### 什么是订阅链接？

订阅链接是机场发给你的一串唯一 URL 地址。客户端通过请求这个链接，可以自动下载并更新机场后台配置的所有最新节点服务器信息。

#### 什么是公网中转节点？

机场在境内租用一台高带宽的服务器（如广州、上海），把你的流量先收集起来，再通过这台境内服务器加密转发到境外落地节点。比你的电脑直接连境外（直连）更稳定、速度更快。

#### 什么是 IPLC / IEPL 专线？

它是机场租用的真正“企业级跨境专线”，流量不经过防火墙（GFW），直接走内网光缆出国。特点是延迟极低、极其稳定，就算大敏感时期也绝对不会断网，但价格很贵。

#### 什么是落地节点？

指流量最终流出的海外服务器。比如你访问谷歌，谷歌看到的 IP 地址就是这个落地节点的 IP（如中国香港、日本、美国等）。

#### 什么是“原生 IP” / 解锁 IP？

该 IP 的注册地与实际机房所在地一致。通常只有这种 IP 才能完美解锁 Netflix、Disney+ 或 ChatGPT 等对风控要求极高的海外服务。

#### 什么是“送中 IP”？

指某个海外节点的 IP 因为长期被大量中国大陆用户使用，被谷歌（Google）的大数据判定为“实际使用者在中国”，导致你用它看 YouTube 时会自动弹出中国大陆的广告，或者 Google 搜索默认变成简体中文。

#### 什么是复用率 / 流量倍率？

机场为了调节成本设置的规则。比如一个节点的流量倍率是 10x，意味着你用这个节点下载 1GB 文件，机场后台会扣除你 10GB 的套餐额度；如果是 0.1x，下载 10GB 只扣 1GB。

#### 什么是审计策略（Audit）？

机场为了自我保护，在服务器端设置的拦截规则。通常会屏蔽 BT 下载、政治极端言论网站、国内涉诈骗/金融风控网站以及特定版权投诉网站。

#### 什么是代理客户端？

专门用来解析机场订阅链接并执行流量转发的软件。本身不带网络流量，常见的有 Clash、Shadowrocket、Sing-box、v2rayNG、Surge 等。

**术语本身不难，难的是各家用同一个词指不同的东西——所以要看它给的具体参数，不是名词。**

## 按使用场景选

使用场景应转成可查的条件，而不是直接转成某个品牌名称。同样的线路标签没有回答设备限制、扣费方式或特定服务当前的支持情况，需要把问题拆开。

### AI 工具：区分地址与规则

1. 先看线路描述及出口IP的类型，确认运营方所指的是哪种属性。出现机房或住宅等字样时，不把标签当成实际服务结果。
2. 再看所需服务的地区支持说明，以及客户端是否将相关请求送往预期路径。页面验证提示也是需要记录的现象，频繁切换可能改变提示。
3. 不要指望某种IP名称替代平台当下的判断。这里涉及线路、IP和客户端规则等因素，是否可用以官方服务当前的支持说明为准。

### 流媒体：把内容地区单独核对

1. 先看IP所指地区与内容的地区范围，明确自己实际需要访问的内容。不要用一个平台名称代替具体的内容条件。
2. 再看住宅或机房等属性，以及当前出现的代理识别提示。同一运营方不同出口的地址来源可能不同，记录不能混用。
3. 不要指望过去的结果一直延续。线路、IP属性与规则只是有关因素，是否可用仍依官方服务当前的支持说明。

### 游戏：先问连接类型

1. 先确认游戏联机需要的UDP转发是否有说明。面向网页的代理与游戏联机需求不能只按相同名称处理。
2. 再看线路是否针对游戏作过安排，并分开记录白天与晚间的连接现象。日常网页访问的结果不能直接代替游戏联机情况。
3. 不要指望普通网页代理自然涵盖游戏需求。没有相应说明时，向运营方确认UDP与所需场景，不自行补出功能。

### 多设备共用：先分清设备与账号

1. 先看允许同时在线的设备数量，别把设备能安装客户端当作账号可无限共用。限制应对应具体套餐与条款。
2. 再看是否会与他人分享账号或订阅信息。信息外泄可能使额度被他人使用，共享方也可能接触使用情况。
3. 不要指望费用分摊会消除账号限制。应分别考虑停用风险、隐私与额度使用，而不是只计算每人支出。

### 低预算：把限额与时间一起读

1. 先看自己需要的额度，以及按月或不限时项目的有效方式。用量不规律时，期限和剩余额度的处理尤其需要明确。
2. 再核对倍率、额度重置与付款周期，并询问低价对应哪些限制。晚间表现与线路实际情况也应留作后续观察项。
3. 不要指望低起价回答全部成本问题。长周期折扣还关联资金占用，不能只为展示金额而忽略服务条件。

- 每种场景都应留下具体项目及适用范围。条款尚未写明的地方，让客服补足说明，不用另一个场景的结论填空。

## 从付款到连上的六个步骤

付款、取得订阅和客户端读取是不同环节，前一项完成不代表后一项已经成功。把每步应有的结果分开核对，连接异常时才容易回到对应位置。

### 付款与领取

### 选择软件与导入

3. 根据设备选择能够读取该格式的客户端，再核对所需配置类型。格式不相容会使列表无法显示，这与连接响应是不同问题。软件名称相近也不能代替格式确认，具体条件应查对应说明。
4. 把订阅导入客户端，观察解析结果。出现invalid config时，查返回的是配置还是提示页。过期或额度耗尽可能收到网页内容，不把此类问题统一归给软件。

### 最小检查与继续定位

5. 先确认配置已读入，并查看客户端的系统代理是否已经启用。再以实际需要访问的对象检查连接，而不是只凭导入完成判断。涉及AI或媒体时记录提示及请求路径，不据一次现象概括服务结果。
6. 不通时先查订阅有效性，再核对格式和系统代理。把解析失败与连接失败分开，无法确认的返回内容交运营方查明。记录软件、项目状态和报错，方便围绕同一环节处理。

- 将日常需要的使用过程与晚间情况分别记录，也观察客服如何处理已提交的问题。单次接通只是当时的结果，不能代替之后的持续使用情况。

## 免费与公益机场怎么看

“免费”只描述某项收费条件，没有同时回答由谁运营、能使用多久以及如何处理数据。看到相关说法时，应先区分它指正式服务的试用，还是未经明确说明的公共分享。

### 先把不同称呼拆开

免费试用可以附带时长或额度限制，限时免费强调的是活动结束点。长期免费则是持续收费方式的说法，不能从这几个字补出有效期限或运营承诺。

公益性质是发布者对定位的自述，不等于已经列明服务条款。转发订阅只说明内容经他人转递，不能用转发者代替实际运营者的身份说明。

| 免费说法 | 应继续确认的内容 |
| --- | --- |
| 免费试用 | 限时还是限量，结束后的处理方式 |
| 限时免费 | 起止条件、结束后是否收费 |
| 长期免费 | 持续条件、限制及费用承担方式 |
| 公益性质 | 谁负责运营、按哪些条款提供内容 |
| 转发订阅 | 原运营者、分享权限与是否多人共用 |

### 用五项问题核对具体条件

1. 找到负责运营与受理问题的一方，确认说明是否由其发布。只有转发内容时，不把转发账号当成运营身份。
2. 读使用条款及退出条件，把免费期间适用的规则单独找出。正式服务的试用与来路不清的公共内容不能混同。
3. 记录可用额度和截止条件，确认是按时间还是按用量结束。限制没有写出时，让运营方提供对应文字，不凭“免费”推定无限。
4. 查是否存在付费升级，并问清结束后按何种条件继续。是否自动扣款也要单独确认，不能把首个周期的安排当成长期安排。
5. 确认公告与反馈的具体出处，再区分发布者解释和个人经历。低价或免费都不直接说明线路实际情况与经营是否持续，记录需要对应时间和对象。

### 风险应落到自己的账号与信息

- 隐私方面，要留意运营成本是否与广告或使用数据记录相关。来路不明的免费内容没有因此获得更少的隐私风险，试用也不等于已有保护承诺。
- 账号方面，试用期间不宜处理重要账号与支付。共享账号还涉及设备上限和使用信息，人数增加不会让原有条款失效。
- 订阅外传可能让他人消耗同一额度，不能把已取得的链接当作可任意转交的公共内容。明文传输如何处理若官方没有说明，应进一步询问数据保护范围。

核对结果应围绕已找到的运营说明与具体限制，而不是寻找一句免费承诺。运营方没有交代的部分保留疑问，不用他人的一次使用经历填补隐私与账号条件。

## 纯净 IP、原生 IP、家宽 IP 三个说法

这几个称呼讨论的不是同一件事，不能合成一个表示使用结果的标签。地址在哪里、属于什么网络用途、是否发生变化，以及已有使用记录，都应分别确认。

| 说法 | 通常指向的内容 | 运营方应解释的范围 | 读者核对方向 |
| --- | --- | --- | --- |
| 纯净IP | 具体判断口径需另行明确 | 具体指哪些记录或判断，结论针对何时 | 让对方明确口径，不只接受标签 |
| 原生IP | 地址归属与实际所在地点相符 | 所指地区、当地分配与实际位置 | 分别核对归属和实际落地说明 |
| 家宽IP | 住宅网络属性，对应家庭宽带用途 | 是否确指住宅而非数据中心类型 | 对照地址类型说明，不与地区属性混用 |

### 原生与住宅需要分别说明

原生的重点在地址归属和实际位置，住宅的重点在分配给家庭宽带这一用途。两项属性不能仅凭一个名称互相替代，运营方需要分别解释所指内容。

### 对“纯净”继续问三件事

1. 问清这个词描述哪一项属性，是地址类型还是已有使用行为。官方没有说明判断口径时，不自行把它解释成某种认证或安全结论。
2. 问清结论对应的时间与对象，尤其是否针对你实际使用的出口。地址历史和平台当前判断是相关因素，不能从笼统宣传推定到所有连接。
3. 问清地址是否固定、何时变化，以及是否与他人共用。动态、静态和共享各自描述使用方式，不是“纯净”的同义词。

### 动静态描述的是变化方式

静态地址保持固定，动态地址会随周期或连接发生变化。需要地址白名单的企业系统或部分API，应单独确认固定地址条件，而不是只看原生或住宅的名称。

- 地址变化可能带来重新验证提示，共享与历史行为也应分开考虑。不能由“会更换地址”推定平台会怎样处理当前请求。
- 固定地址也没有回答住宅属性或实际地区。将变化方式、用途和位置分别列清，才能知道运营方真正说明了哪些项目。

### 与 AI 服务及流媒体的关系

服务页面上的地区提示、代理识别或账号验证，可能与IP类型、归属及历史行为有关。线路类型与客户端规则也属于需要同时观察的因素，不能只靠某个IP名称解释全部现象。

AI服务和媒体平台会调整自身支持条件，当前提示只反映当时环境。阅读这些属性时，应以官方服务现行支持说明对应具体需求，不将任何一类地址写成长期结果保证。

## 梯子、机场、VPN：三个说法分别指什么

「梯子」「机场」「VPN」在日常介绍中会指向不同层面，本章将机场限定为代理订阅运营方这一社区称呼，不把它当技术标准名。已有问答介绍过这些称呼，这里改看协议和系统文档分别描述什么，不再展开服务选购。

### 按产品实际提供的对象辨别称呼

看到一段介绍，可以先分辨它提供订阅配置、发布客户端，还是描述系统接口。服务来源、软件与协议并不是同一对象，名称相近也不能替代这一步区分。

| 说法 | 技术上通常对应 | 官方文档里能核对到的描述 |
|---|---|---|
| 梯子 | 日常对连接工具或方式的泛称，不对应单独协议 | 分别查 HTTP 隧道、SOCKS 或系统接口，不把口语当协议定义 |
| 机场 | 本章约定指代理订阅服务的运营方 | 协议规范描述通信动作，不替运营方说明具体条款 |
| VPN | 应用或系统级连接机制，要继续看具体项目 | Android 描述虚拟接口及 IP 包处理，Apple 提供 Personal VPN 配置管理接口 |

表格用于确定下一步该读哪份资料，没有把这些称呼排成能力等级。看到某项介绍只给一个口语名称时，仍缺少协议或软件层面的对应信息，不能由名称补齐。

### CONNECT 说明的是隧道动作

RFC 9110 的 CONNECT 让代理连接目标，请求中要带目标主机与端口。建立隧道之后，代理在两个方向转发数据，规范没有在这里替每种实际产品给出完整的可见信息清单。

隧道还能在其上使用 TLS，但建成隧道与采用 TLS 是两项描述。[RFC 9110](https://www.rfc-editor.org/rfc/rfc9110) 可用于核对前者，不能只凭出现代理一词就确认后者的具体条件。

### SOCKS 的层级与机密性分别阅读

RFC 1928 把 SOCKS 放在应用层和传输层之间，涉及 TCP 与 UDP 通信。它还说明自己不提供网络层网关服务，例如转发 ICMP，这一范围不能被改写成对所有代理软件的统一定义。

机密性取决于协商的认证及封装方法，而不是协议名字本身作出的保证。对应条文在 [RFC 1928](https://www.rfc-editor.org/rfc/rfc1928)，这里不从账号、口令或中转名称推断连接用了哪种保护。

### 系统文档描述接口，不替工具作优劣比较

Android 的 VpnService 用于让应用建立虚拟接口，并配置地址及路由，应用通过返回的文件描述符处理 IP 包。[Android VpnService 官方文档](https://developer.android.com/reference/android/net/VpnService) 描述的是平台能力，不能用它证明任意应用已经采用相同配置。

Apple 的 NEVPNManager 则用于在 iOS、macOS 创建和管理 Personal VPN 配置。[Apple NEVPNManager 官方文档](https://developer.apple.com/documentation/networkextension/nevpnmanager) 与 Android 文档是各自系统的说明，不是一张由官方给出的代理与 VPN 对照结论表。

OpenVPN 官方介绍涉及 SSL/TLS 网络扩展，并明确它不是网页应用代理。只能保留该项目对自身的描述，不能据此断言所有带 VPN 名称的工具都具有相同界面或范围。

### 读产品介绍时对照它提供的对象

介绍写的是订阅配置，就先记录提供方与内容；写的是应用，就看它的发布与系统说明；写的是接口或协议，则读对应规范。这个分类是阅读方法，不把任何一类名称当作已经确定的连接能力。

例如 CONNECT 文档的成功响应会使双方转入隧道状态，SOCKS 文档则分别描述连接与 UDP 关联，后者还随对应 TCP 连接结束而终止。这些过程属于具体协议，不能直接拿来解释一家运营方的条款，也不能替应用界面补出同名按钮。

### TLS 与平台披露回答另外两类问题

RFC 8446 把通道建立后数据只对端点可见列为机密性内容，同时交代数据长度不被隐藏。这里的端点保护不能替代客户端来源、运营方身份或具体数据用途的说明。

Apple 对 VPN 应用还要求使用前披露收集哪些数据及用途，并在政策中作出相应承诺。这是应用审核要求，与协议工作层次不同，不能因为读到了平台规则，就把某个产品的实际行为写成已证明。

## 排障速查表：官方资料里写明的几类故障与处理

这张表把现象、已有解释和处理条件分开，范围限于官方资料明确涉及的项目。没有原因文字的地方只保留处理顺序，不从错误提示推定证书、账号或运营状态。

### 对照现象阅读官方处理条件

| 现象 | 官方资料里写的原因 | 官方资料里写的做法 |
|---|---|---|
| client error(Connect) | 资料没有在此指定单一根因 | 先换用另一种配置导入方式 |
| 链接配置方式仍报错 | 文档给出后续选项，未将错误直接归因 | 文档列“允许无效证书（危险）”选项，随后保存重试；此项有安全风险 |
| 某程序未采用系统代理 | 系统代理依赖应用读取约定，不能承载 UDP 代理；TUN 涉及虚拟网卡 | 阅读系统代理与 TUN 的分别说明，再对应程序所需的 TCP、UDP 条件 |
| 开启防火墙后相关 TUN 栈不可用 | mihomo 文档对 system、mixed 写有这一限制 | 按文档为实际内核程序设置防火墙放行 |
| 两份资料给出不同默认 stack | Verge 文档写 GVisor，mihomo 文档写 mips | 两种来源并排保留，依据实际版本和相应页面核对 |
| 不同客户端取得的配置需确认 | 服务端按请求头中的 User-Agent 识别客户端，返回相应配置 | 文档提供携带 UA 请求，检查是否返回 YAML 的思路 |
| HTTP、SOCKS、Mixed 接入未启用 TLS | 这是文档的公网暴露提醒，不是已确定发生的故障原因 | 不将这些缺少 TLS 的入站直接开放至公网 |

导入提示与证书选项来自 [Clash Verge Rev 官方文档站](https://clash-verge-rev.github.io/)。内核配置边界另看 [mihomo 官方文档站](https://wiki.metacubex.one/)，不能仅凭一张表把本机现象确认成某一行原因。

### 导入错误先按顺序读，不替选项省略风险

client error(Connect) 对应的官方起点是换一种导入方式，不是先宣告配置损坏。文档没有在该提示下确定唯一根因，本表同样不补诊断结论。

链接配置继续报错时，文档才列出无效证书选项及保存重试。安全风险要与选项同时阅读，不能把它缩写成无条件放宽校验的默认操作。

### 应用、虚拟网卡与服务分别核对

某个应用是否读取系统代理，和 TUN 通过虚拟网卡处理 TCP、UDP，是官方文档中的不同描述。此处只用这层区别定位阅读方向，不复述已有问答，也不保证换模式就能解决任意应用的连接问题。

服务模式由独立服务进程启动内核，使 TUN 可以在非管理员身份下启动。退出 Verge 后服务仍在后台，不能把窗口关闭当成服务已经结束的依据。

### 防火墙说明与默认堆栈并列保留出处

Verge 资料列出需要放行的内核为 verge-mihomo 和 verge-mihomo-alpha。system、mixed 的条件来自 mihomo 的 TUN 文档，不把这两种栈的限制扩展到没有说明的其他栈。

截至 2026-10-22，官方页面显示 Verge 文档将默认堆栈写为 GVisor，而 mihomo 文档写 mips，以官方页面为准。这里不把两处拼成一个统一默认，仍以实际版本为准。

### 返回内容检查和公网接入不是同一种排查

UA 检查针对服务端返回了什么，不能只按链接相同就假定不同客户端取得内容相同。这里只保留文档的检查目标，不列请求命令，也不把结果未取得写成已经返回 YAML。

文档的 UA 检查思路举了 PowerShell 和 curl 这类请求工具，但本章不列具体命令。要分清的是请求标识与收到的内容，不从同一个地址推定每次返回格式相同。

默认 stack 的资料差异也不是本机故障诊断，只说明两处文档给出了不同默认。当前配置采用哪个栈，要回到实际版本及其文档，不能将默认名称直接填进所有异常的原因列。

无 TLS 的接入提醒限定在 HTTP、SOCKS 与 Mixed 面向公网的情况。它不是对其他入站或任意客户端的通用结论，也不提供开放公网的配置教程。

## 关于准确性

这份资料的原则和来源站点一致：

- **不提供实测数据。** 这里没有延迟、带宽、丢包率的测试数值，也没有测速截图——那类结果依赖测试时间、本地带宽和当时负载，无法复现。

- **给方法而不是结论。** 例如线路类型可以用 `BestTrace`/`mtr` 路由追踪自行验证，解锁状态可以用开源脚本 [RegionRestrictionCheck](https://github.com/lmc999/RegionRestrictionCheck) 自测。
